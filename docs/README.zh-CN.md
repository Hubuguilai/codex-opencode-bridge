# Codex ↔ OpenCode 本地桥接

这是从实际可用原型整理出的私有实验项目，用官方 OpenCode v2 会话接口提供
Chat Completions 和 Responses 文本接口。它不提供账号、密钥或免费额度。

## 运行

需要 Node.js 22+ 和单独安装的 OpenCode v2（当前验证目标是 2.0.18）。

```sh
npm ci --ignore-scripts
node bin/bridge.mjs init
npm start
```

如果找不到 OpenCode，将 `OPENCODE_BIN` 设置成已安装可执行文件的绝对路径。
默认桥接端口为 4396，内部 OpenCode 端口为 4397。每次运行用独立空目录，
本地鉴权令牌放在仓库外的用户数据目录；运行时会显示令牌文件位置，不打印令牌。
Ctrl-C 会停止桥接和它启动的 OpenCode 进程。

## 当前能力

- 两种文本 API，普通响应与 SSE。
- 轮询上游快照并立即转发新增文字；上游若只在最后提供文本，则只能最后一次返回。
- 明确拒绝不支持的图片、工具调用、推理强度参数与会话续接，避免伪装成已经支持。
- 超长输入明确报错，不静默截断；字节上限与模型 token 上限是两回事。
- 本地鉴权、并发限制、断开取消、超时和已知会话清理。

**尚不能作为完整的 Codex 编程后端。** 安装桥接本身不会自动把模型加入 Codex
下拉菜单。现有 Router 的模型目录与接口字段需要单独适配；普通 Codex 请求会带工具，
此版会拒绝这些请求。你之前能聊天的本地原型会忽略工具字段，本项目改成了明确报错。

OpenCode 的 Plan 模式仍然可能使用其自身工具与配置。空工作目录不是系统级沙箱，
不能保证没有文件读取或内部工具执行。不要把客户端工具拒绝等同于上游完全禁用工具。
